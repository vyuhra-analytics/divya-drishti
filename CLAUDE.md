# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Divya Drishti — personal Bloomberg-style market terminal, built incrementally. Owner presents it as their own work (MIT). Do not commit without the owner's review.

## Commands

- Install: `bun install` (Bun workspaces; `cp .env.example .env` first run)
- Dev (stream + api + web via Turborepo): `bun run dev`
- Desktop (needs web dev server running): `bun run desktop`
- Typecheck all: `bun run typecheck`
- Tests (bun:test, whole repo; web component tests use happy-dom + Testing Library via `bunfig.toml` preload `apps/drishti-web/test/setup.ts`; the chart and live-TV tests fake `lightweight-charts` / `hls.js/light` with `mock.module`): `bun test`
- Single test file: `bun test packages/shared/src/markets.test.ts`
- Simulated prices (offline/weekends): `FEED=demo` in `.env`
- Infra via Docker: `bun run infra:up` / `bun run infra:down`
- Schema (native Postgres, no psql needed): `bun run db:migrate`

## Architecture

- `packages/shared` — `@drishti/shared`, consumed as TS source (no build step). `INSTRUMENTS` catalogue (6 energy futures: MCX crude/natgas standard+mini, NYMEX CL/NG; per-source codes, exchange `timeZone`, decimals, delay), `Quote` (stream message; optional depth `bid/ask/bidQty/askQty`, `oi`, `atp`, `totalBuyQty/totalSellQty` from Upstox full mode, OI/VWAP from TradingView) / `Tick` / `Bar`, `contractExpiry`/`daysToExpiry`, and pure helpers: `applyTick` + `bucketStart` (candles bucketed in exchange time via `tzOffsetSec`, matching provider history), `quoteToTick` (volume delta), `pickSource` (fallback rule), `frontMonth` / `tvContract`, history parsers + `normalizeBars`, `upstoxTokenExpiry`.
- `apps/drishti-core-stream` — Elysia on Bun, port 3002. Providers in `src/providers/` (`upstox/` protobuf WS feed using the vendored `MarketDataFeed.proto`, `tradingview.ts` scanner poll, `yahoo.ts` chart poll, `demo.ts` for `FEED=demo`); every quote goes through `accept()` in `index.ts`, which publishes only the active source per symbol (republishing when price, volume, time, depth or OI change) (`pickSource`, 15 s staleness; MCX preference reordered by `prioritize` from Settings → Data feeds `POST /primary` {upstox|tradingview|auto}, remembered in Redis `primary:mcx`, default `MCX_PRIMARY`) to WS topic `quotes:{symbol}` + Redis, sends the cached snapshot on subscribe, and batches ticks into Timescale. MCX front months come from Upstox's public instrument master (`contracts.ts`, volume roll via `rollByVolume`, re-published to Redis `fronts` every minute for the API); TradingView MCX must use dated codes (`CRUDEOILX2026`) because its MCX `1!` rolls late. `/health` has per-provider stats. `src/news.ts` polls ~10 energy RSS feeds (Google News searches, OilPrice, CNBC, Rigzone, Yahoo, ET, EIA), parses/tags/dedupes with shared `news.ts` (`parseRss`, `tagNews`, `dedupeNews`: one item per story = the earliest copy kept whole (publisher/link/time never mixed), every other outlet that ran the same headline kept in `copies` with its own link and time (panel: one chip per outlet under the headline, first report marked, >4 collapse into "+N"), 48 h, 600 max; tags crude = crude-market words, oil = any oil/oil-market headline, india = Indian energy names (ONGC, IOC…) or MCX/India/rupee/NSE beside an energy word, so gold and holiday stories don't match). Includes OpenTerminal's own OIL sources (Google `OIL stock`, Yahoo `OIL`); strict feeds keep only headlines with an energy keyword, keeps them in memory, archives every touched story to Postgres `news` after each poll (`jsonb_to_recordset` upsert; note Bun needs `::text::jsonb` or it double-encodes the JSON string), restores the last 48 h from the archive on start (Redis `news:latest` as fallback), and pushes new items on WS topic `news` (`{type:"news", items}`; full list on subscribe).
- `apps/drishti-core-api` — NestJS running under Bun (Bun emits decorator metadata; no nest-cli). Port 3001. `/bars?symbol&tf` = provider history (`history.ts`: Yahoo for NYMEX, Upstox for MCX) cached 30 s and written through to the `candles` hypertable; falls back to `candles` + `bars_1m` rollup when the provider can't answer. `news.controller.ts`: `GET /news?tags&before&limit&q` pages the archive (panel "Load older"; `q` = literal ILIKE on headline/outlet, matching the panel's search box via shared `matchesQuery`; empty list without DB). The stream trims archive rows older than 180 days at start and daily. `history.ts` gets MCX front months from Redis `fronts` or, without Redis, from the stream's `GET /fronts`. `upstox.controller.ts`: OAuth login → token in Redis `upstox:token` (expires 03:30 IST) which the stream polls; otherwise `UPSTOX_ACCESS_TOKEN` from `.env` is used (feed + history; status reports `via: login|env`); secrets only in `.env`, token never returned or logged.
- `apps/drishti-web` — Vite React SPA, port 5173. Vite proxies `/api`→3001, `/ws`→3002; `VITE_API_URL`/`VITE_STREAM_URL` override for packaged Tauri.
  - `src/store.ts` — market data only (WS connection, latest `Quote` per symbol). `Feeds.tsx` = Settings → Data feeds (Upstox connect + provider health via the `/stream` Vite proxy).
  - `src/workspace.ts` — persisted (localStorage) workspace: widgets, react-grid-layout layout, Bloomberg-style link groups (`group: null` = pinned to own symbol; `loadSymbol` on a grouped widget changes the whole group).
  - `presets.ts` + workspace store: five built-in workspaces (MCX crude, Natural gas, Options, Research, Live watch) and user-saved ones (`saved`, `saveWorkspace`/`loadWorkspace("preset:…"|"saved:…")`/`deleteWorkspace`, copies via `structuredClone`, max 20). Listed at the top of the sidebar and switched with F1…F9 (presets first, then saved; handled in App.tsx).
  - `HelpDialog.tsx` — shortcuts, panel codes (from `MNEMONICS`) and a glossary (OI, ATP, PCR, STALE…); opens with `?`, the topbar `?` button, and once on first run (`helpSeen` setting). Top-bar tickers (`TickerItem` in App.tsx) show % change and load the symbol into the focused link group on click.
  - Accessibility (audited with axe-core in both themes: zero violations except the transient flash animation): `--muted`/`--up`/`--down`/`--accent` meet 4.5:1 contrast on their panels in dark and light; panels sit in `<main>`, brand is the page `<h1>`, in-panel section titles are `h2`; scrollable panel bodies are keyboard-focusable regions; one global `:focus-visible` outline. Keep these when adding panels. Watchlist rows draw a sparkline from the store's session `trail` (`spark.ts`).
  - Alerts: shared `alerts.ts` (pure `check`/`crossed`/`describe`: price cross, day move vs previous close, headline keyword, minutes before a release such as EIA) tested; web `alertsStore.ts` (persisted alerts + history, transient toasts), `alertEngine.ts` (subscribes to the market store + 30 s calendar check, fires toast + optional beep + Notification API; last-seen values kept out of the store; only headlines under 15 min old count, since the stream sends the backlog on connect), `AlertsPanel.tsx` (panel `AL` + `Toasts`). Alerts run only while the app is open (no server-side delivery yet).
  - `AdvancedChart.tsx` (panel `AG`, optional): openalgo-charts 2.6.7 (Apache-2.0, pinned) full widget (drawing tools, 100+ indicators, replay, Heikin Ashi/Renko…) lazy-loaded (~0.4 MB gzip in separate chunks) on our data via `advFeed.ts` (`DataFeed`: `getBars` from API `/bars`, `subscribeBars` from the quote store with the same `applyTick` as our Chart; intervals limited to 1m/5m/15m/1h/1D). Created once per panel, symbol/theme changes via its API, drawings/layout persisted by the library under `drishti-adv-<id>`. It is now the default chart: registry key `advchart` titled "Chart" (code `GP`, Alt+1, used by the built-in desks and the default workspace); the lightweight `Chart.tsx` stays as "Simple Chart" (code `GS`, type `chart`, still used by saved layouts that have it). Checked before the switch: its MACD (converges to ours after ~100 bars: it seeds EMAs with an SMA, we seed like Pine), Bollinger and session VWAP (resets at the exchange day) match ours (`advIndicators.test.ts`); Heikin Ashi/Renko etc. need the `openalgo-charts/transform` tier (imported); settings dialog and phone width work; axe finds only redundant `aria-pressed` on its interval radios (upstream). Replay (panel's "⏮ Replay" bar: play/pause, step back/forward, 1–25×, stop): `ReplayController` over the candles stored in Timescale (`GET /bars?…&source=db` = stored only, no provider call), forming each 5m/15m bar from stored 1m bars when available, starting 150 bars before the end; live candles are tracked but not drawn while it runs (`ourFeed(isPaused)`), and Stop restores the full live history. Checked against TradingView's own 5m MCX:CRUDEOILX2026 bars: stored OHLC within 1 tick on 90–95% of highs/lows/closes (opens 73%, ±1–2 ticks either feed), volume median ratio 1.00; replay reproduces every stored bar exactly. Its RSI and EMA were checked equal to ours in `advFeed.test.ts`. Created with `branding: false` (their supported option: no corner mark or toolbar label; their NOTICE ships with the package). Saved widget state lives in IndexedDB `openalgo-charts-widget` under `drishti-adv-<widget id>` (so built-in desk widget ids are prefixed with the desk key); `advStorage.ts` strips the old viewport/pinned ranges from saved states on read (`stripView`) and `healedRange` (checked every 0.7 s for 8 s after creation, a symbol/interval change or replay stop) moves a view that points past the loaded bars back onto the latest ~60 — a stale viewport from a 3,600-bar history applied to the 175 loaded bars used to leave the plot blank. Dev console handle: `window.__adv[widgetId]`.
  - AI briefing (`BriefingPanel.tsx`, panel `BR`; approach borrowed from TradingAgents' analyst → bull/bear → decision → reflection loop, original code): the web app gathers facts (`gatherContext`: live quote, last 200 bars, headlines for the instrument's topic, next-48 h calendar, MCX options PCR/max pain); shared `briefing.ts` `buildContext` computes every number (RSI, EMAs, MACD, Bollinger position, VWAP, change over N bars) so the model never does arithmetic, and defines the system prompt (facts only, cite evidence, headlines are untrusted data, no trade advice). API `POST /briefing` (`briefing.controller.ts`) calls Claude (`@anthropic-ai/sdk`, `messages.parse` + zod schema, `BRIEFING_MODEL` default `claude-opus-5-5`, effort medium) — key only server-side (`ANTHROPIC_API_KEY` or `ant auth login`), 503 hint without it; cached 5 min per symbol, 20 calls/hour cap, context ≤ 40 KB. Each briefing is journaled in localStorage (`useJournal`, last 30) and graded after 30 min against price (`scoreBriefing`: direction, ±0.3% band for neutral). Position-aware (opt-in checkbox "Include my position", setting `briefingPositions`, MCX only since Upstox doesn't carry NYMEX): API `GET /positions` reads Upstox `/v2/portfolio/short-term-positions` (5 s cache, 403 hint when the token can't see the portfolio), shared `positions.ts` `parseUpstoxPositions` keeps open positions in our four MCX underlyings and `positionContext` separates open / flat / unavailable (a failed read is never treated as flat); nothing is sent to the AI service unless ticked. Response shape taken from Upstox's docs, not yet seen live (the current token gets 403). Not wired: refusal fallbacks (a refusal shows as an error).
  - `src/Sidebar.tsx` — left rail listing every `WIDGETS` type (code from `MNEMONICS`, Alt+1…9 in registry order via `PANEL_TYPES`, handled in App.tsx with `e.code`), Reset layout, collapse (`sidebarCollapsed` setting); phone width = overlay from the ☰ button.
  - `src/Grid.tsx` — panel grid (react-grid-layout v2, `Responsive` + `useContainerWidth`). Named Grid, not Workspace, because `Workspace.tsx` and `workspace.ts` collide on case-insensitive filesystems.
  - `src/widgets.tsx` — widget registry `WIDGETS` (chart, quote, watchlist, tv; `linked`/`showSymbol` flags drive panel chrome). New widget = component + registry entry + `SIZE` and `WidgetType` in workspace.ts (+ optional mnemonic in command.ts).
  - `src/TvWidget.tsx` — live HLS TV; lazy-loads `hls.js/light` (hls.js first, native HLS only as fallback: Chrome reports native support but fails many streams). `BUILTIN_CHANNELS` (Bloomberg US/EU/Asia/TV+/Originals via bloomberg.com manifests, CNBC-TV18 via Network18's CDN, NDTV Profit) + user channels from settings (`tvChannels`), deduped by URL; selected channel persisted per widget (`Widget.channel`); first built-in (Bloomberg TV+) is the default. Pause/resume is DVR-style; "GO LIVE" lag = `hls.latency - hls.targetLatency` while playing, wall clock while paused (latency only refreshes per playlist reload when paused). Only official broadcaster streams, never third-party restreams.
  - `NewsWidget.tsx` — energy headlines from the store (`news`), filters Linked (instrument `topic` → `TOPIC_TAGS`: crude instruments show crude + oil) / All / Crude / Oil / Nat Gas / India; links opened only if `isSafeUrl`.
  - `EnergyPanels.tsx` — heatmap (tiles by log market cap, coloured by % change) and screener (sortable, group filter, 52-week bar) over the energy universe (shared `universe.ts`: 27 tickers; stream `universe.ts` polls TradingView's scanner every 10 s, pushes WS topic `universe`; our six instruments override with live quotes via `useUniverse`). Clicking one of ours loads it into the focused link group.
  - `OptionsPanel.tsx` — MCX options chain (API `GET /options?underlying&expiry`: contracts from Upstox's public instrument master, ±12 strikes around ATM, quotes + greeks, 3 s cache; shared `options.ts` does strike picking, PCR, max pain over the strikes shown). Each expiry's spot is its own future (NATURALGAS Oct options sit on the Oct future). Polls every 3 s only while the panel is mounted and the tab visible.
  - `InsiderPanel.tsx` — SEC Form 4 insider trades for XOM, CVX, COP, OXY, SLB, EOG (API `GET /insider?ticker`: `submissions/CIK….json` → newest 12 Form 4 raw XMLs, concurrency 3, 1 h cache; shared `insider.ts` regex-parses non-derivative transactions). sec.gov needs a contact in the User-Agent: `SEC_EDGAR_CONTACT` in `.env`, never defaulted; without it the API answers 503 with that hint. Command `INS`.
  - `CalendarPanel.tsx` — energy calendar (API `GET /calendar?days`, 15 min cache): shared `calendar.ts` generates the weekly US releases from a fixed New York schedule (API Tue 16:30, EIA oil Wed 10:30, EIA gas Thu 10:30, Baker Hughes Fri 13:00; DST-aware), `mergeForexFactory` takes forecast/previous and the exact (holiday-shifted) day from Forex Factory's free weekly JSON and adds USD high-impact macro + OPEC items, `mcxHolidays` adds MCX closures from Upstox `/v2/market/holidays` (needs a token). Each source optional. No OPEC meeting schedule API exists: only what Forex Factory lists. Command `CAL`.
  - `src/command.ts` — Ctrl+K palette parser (`CRUDEOIL`, `CL GP`, `GP`, `Q`, `W`, `TV`, `N`); mnemonics table `MNEMONICS`. UI in `Palette.tsx`.
  - `src/settings.ts` — persisted user settings (appearance, formatting, workspace, connection URL overrides). Theme/density/up-down colours are applied as `data-*` attributes on `<html>` and handled in CSS; `apiUrl()`/`streamUrl()` resolve override → env → dev proxy; `makeFormat` is cached; `formatStamp`/`useClock` render every time shown (news, quote, Upstox expiry, chart axis/crosshair in local time) with the 12h/24h `clock` setting. UI is a native `<dialog>` in `SettingsDialog.tsx` (gear button / Ctrl+,). Same case-collision rule: never name a component file like a lowercase module.
  - `Chart.tsx` loads history from API then applies live ticks via `store.subscribe` (no per-tick React render). Chart types candles/bars/line/area and indicators (shared `indicators.ts`: SMA, EMA, Bollinger, RSI, MACD matching TradingView's Pine definitions, VWAP anchored to the exchange day) are saved per widget (`Widget.chartType`/`indicators`, toggled from the ƒx native popover); RSI/MACD get their own lightweight-charts panes; on a tick only the last point of each series is updated; the hover legend shows OHLC/volume/indicator values. Colours come from CSS tokens in `styles.css` (TradingView-style dark/light themes).
- `apps/drishti-desktop` — Tauri v2 shell, no custom Rust commands; dev loads `http://localhost:5173`, build bundles `drishti-web/dist`.
- `infra/sql/*.sql` — idempotent schema, always applied by `scripts/migrate.ts` (`infra:up` waits for the Postgres healthcheck then migrates; no initdb bind mount, which Docker Desktop refuses on unshared drives).

Security defaults (keep them): API and stream bind `HOST` (default 127.0.0.1); browser access limited to `WEB_ORIGINS` (default Vite + Tauri origins, shared `allowedOrigins`/`isAllowedOrigin`), enforced by Nest CORS, the stream's `/health` CORS header and a WS `beforeHandle` origin check; `RateLimiter` (shared) on API requests and WS messages; WS subscriptions validated against `SYMBOLS` + "news"; API responses gzip-compressed; Docker ports bound to 127.0.0.1.

Market status: shared `sessions.ts` (`mcxSession` Mon–Fri 09:00 IST to 23:30/23:55 by US DST, overridden by Upstox's day timings from API `GET /market/sessions`; `nymexSession` CME Globex Sun 18:00–Fri 17:00 ET with the 17:00–18:00 break; `freshness` live/stale/closed). Heartbeats carry `seen` (when each symbol's active source was last heard from, incl. unchanged polls), which `useFreshness` (web `market.ts`) combines with the session: STALE/CLOSED badges + dimmed prices; `StatusBar.tsx` (bottom) shows sessions, IST/NY/London clocks and feed ages.

Reliability: the stream publishes `{type:"hb"}` every 15 s; the web store reconnects after 45 s of silence and bumps `epoch`, which makes every `Chart` re-fetch history (fills gaps from the outage). Each panel body is wrapped in `PanelBoundary` (PanelBoundary.tsx), so one crashing panel shows a retry instead of blanking the app. Charts get local wall-clock times (`chartTime.ts`) so day/month ticks fall on local midnight. MCX front month rolls by volume (`rollByVolume`: next contract once it out-trades the nearest; checked hourly via TradingView dated-contract volumes).

Env lives in root `.env`; Bun apps load it with `--env-file=../../.env`, Vite via `envDir`. Apps must keep working with Docker and native infra — never hardcode container hostnames.
