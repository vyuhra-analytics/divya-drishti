# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Divya Drishti — personal Bloomberg-style market terminal, built incrementally. Owner presents it as their own work (MIT). Do not commit without the owner's review.

## Commands

- Install: `bun install` (Bun workspaces; `cp .env.example .env` first run)
- Dev (stream + api + web via Turborepo): `bun run dev`
- Desktop (needs web dev server running): `bun run desktop`
- Typecheck all: `bun run typecheck`
- Tests (bun:test, whole repo; web component tests use happy-dom + Testing Library via `bunfig.toml` preload `apps/drishti-web/test/setup.ts`; the live-TV tests fake `hls.js/light` with `mock.module`): `bun test`
- End-to-end (real browser, against the running dev stack): `bun run e2e [name ...]` (`e2e/run.ts`, `playwright-core` driving the installed Chrome or Edge, no browser download; start `bun run dev` first, it exits 2 with that hint if the stack is down). A small runner of its own, not `bun test` (which preloads a fake DOM). Twelve checks: app loads with no script errors, live prices reach the top bar, Costs, Strategy tester, Paper trading (buy, close, journal note; skipped when the market is closed), Data quality, and the COT, chokepoints, curve, recap and EIA panels render real data and show no false OUTDATED badge. Screenshots of every panel go to `e2e/screenshots/` (gitignored): read them to look at the panels. First run found two bugs the component tests could not: every EIA row marked OUTDATED (freshness budgets ignored publication lag) and two table-alignment slips. Gotcha: Vite's dev cache can serve a stale transform when a file is edited twice in quick succession (a panel crashed with "Outdated is not defined" although the import was in the file): `touch` the file or restart the web server.
- Live smoke test: `bun run smoke` (`scripts/smoke.ts`, needs the dev stack): 40 checks over every API route with a good and a bad request (bad input must be a 400, never a 500), the stream's health and WebSocket (a live quote and a heartbeat arrive), and the security defaults (a foreign website can neither read the API nor open the WebSocket; unknown and internal topic names are ignored without data). Read-only: it creates and removes one never-firing server alert and sends nothing to Telegram; Test layers, cheapest first: pure unit tests in `packages/shared`, component tests (happy-dom), API controller tests (`apps/drishti-core-api/src/*.test.ts`: a fake database and fake Telegram, validation before any network, mutation-checked: weakening a limit makes them fail), recorded-fixture contract tests, then `bun run smoke` and `bun run e2e` against the live stack. A root `tsconfig.json` (legacy decorators, no files) exists only so `bun test` from the repo root can load Nest controllers.
- Single test file: `bun test packages/shared/src/markets.test.ts`
- Simulated prices (offline/weekends): `FEED=demo` in `.env`
- Infra via Docker: `bun run infra:up` / `bun run infra:down`
- Schema (native Postgres, no psql needed): `bun run db:migrate`
- Tidy the database: `bun run db:clean` is a dry run, `bun run db:clean -- --apply` removes what nobody reads: the audit trail of the throwaway `e2e` and `smoke` paper accounts (the audit log is append-only, so every e2e/smoke run leaves rows), candles, ticks and rolls of symbols no longer tracked (built-ins plus the `custom_instruments` table; it stops if that list cannot be read), and option OI snapshots older than 7 days. Never touches your own accounts, alerts or tracked symbols. Ticks are not its business: they expire by themselves (below).
- **Tick retention** (`infra/sql/009_tick_retention.sql`, applied by `db:migrate`): raw `ticks` (about 25,000 a day) are dropped after 90 days by a daily Timescale job, whole 7-day chunks at a time; the 1m bars in `bars_1m` stay for good. The aggregate's refresh policy covers all history (`start_offset NULL`, the 001 migration no longer adds its own: two policies on one aggregate are refused, which broke re-running `db:migrate`), so late or restored ticks are folded into `bars_1m` before retention can drop them. Proven on a synthetic symbol 150 days old: refreshed into 6 bars, the retention job removed the ticks and kept the bars. To change the 90 days edit the SQL and re-run `db:migrate`; `db:clean` warns if ticks older than 100 days exist (the job is not running).
- **Native infra without Docker (Windows, set up 2026-10-22, same `.env` URLs)**: PostgreSQL 17 as service `postgresql-x64-17` on 5432 (`winget install PostgreSQL.PostgreSQL.17` with `--override "--mode unattended --unattendedmodeui none --superpassword <pw> --serverport 5432 --servicename postgresql-x64-17 --enable-components server,commandlinetools"`), TimescaleDB 2.31.0 from the zip on [the GitHub release](https://github.com/timescale/timescaledb/releases) (`timescaledb-postgresql-17-windows-amd64.zip`: copy its `*.dll` into `PostgreSQL\lib` and `timescaledb.control` + `timescaledb--*.sql` into `share\extension`, as administrator; its `setup.exe` is unsigned, so this was done by hand), then `ALTER SYSTEM SET shared_preload_libraries='timescaledb'`, `listen_addresses='localhost'` (the installer listens on all interfaces), `timescaledb.telemetry_level='off'` and a service restart; a `drishti` role (superuser, as in the Docker image, because `CREATE EXTENSION timescaledb` needs it) and database with the password from `DATABASE_URL`, then `bun run db:migrate`. Redis is **Memurai Developer 4.1.2** (Redis 7.2.5 compatible, service `Memurai`, 127.0.0.1:6379; `winget install Memurai.MemuraiDeveloper` failed with 1603 because its custom actions could not create a temp directory, and succeeded with an elevated `msiexec /i … /qn` run with `TEMP=C:\Windows\Temp`). The old Docker data was copied across (paper trades and audit, news, option OI, `candles`, `ticks`; hypertables need `COPY`, since a data-only `pg_dump -t` of the parent table skips the chunks) and the volume `divya-drishti_pgdata` is untouched, so `bun run infra:down` and Docker still work as a fallback: stop the native services first, both want 5432 and 6379. Another PostgreSQL 18 service on 5433 belongs to something else; leave it alone. The superuser password is not in the repo: reset it with an elevated `psql` if lost.

## Architecture

- `packages/shared` — `@drishti/shared`, consumed as TS source (no build step). `INSTRUMENTS` catalogue (6 energy futures: MCX crude/natgas standard+mini, NYMEX CL/NG; per-source codes, exchange `timeZone`, decimals, delay), `Quote` (stream message; optional depth `bid/ask/bidQty/askQty`, `oi`, `atp`, `totalBuyQty/totalSellQty` from Upstox full mode, OI/VWAP from TradingView) / `Tick` / `Bar`, `contractExpiry`/`daysToExpiry`, and pure helpers: `applyTick` + `bucketStart` (candles bucketed in exchange time via `tzOffsetSec`, matching provider history), `quoteToTick` (volume delta), `pickSource` (fallback rule), `frontMonth` / `tvContract`, history parsers + `normalizeBars`, `upstoxTokenExpiry`.
- `apps/drishti-core-stream` — Elysia on Bun, port 3002. Providers in `src/providers/` (`upstox/` protobuf WS feed using the vendored `MarketDataFeed.proto`, `tradingview.ts` scanner poll, `yahoo.ts` chart poll, `demo.ts` for `FEED=demo`); every quote goes through `accept()` in `index.ts`, which publishes only the active source per symbol (republishing when price, volume, time, depth or OI change) (`pickSource`, 15 s staleness; MCX preference reordered by `prioritize` from Settings → Data feeds `POST /primary` {upstox|tradingview|auto}, remembered in Redis `primary:mcx`, default `MCX_PRIMARY`) to WS topic `quotes:{symbol}` + Redis, sends the cached snapshot on subscribe, and batches ticks into Timescale. MCX front months come from Upstox's public instrument master (`contracts.ts`, volume roll via `rollByVolume`, re-published to Redis `fronts` every minute for the API); TradingView MCX must use dated codes (`CRUDEOILX2026`) because its MCX `1!` rolls late. `/health` has per-provider stats. `src/news.ts` polls ~10 energy RSS feeds (Google News searches, OilPrice, CNBC, Rigzone, Yahoo, ET, EIA), parses/tags/dedupes with shared `news.ts` (`parseRss`, `tagNews`, `dedupeNews`: one item per story = the earliest copy kept whole (publisher/link/time never mixed), every other outlet that ran the same headline kept in `copies` with its own link and time (panel: one chip per outlet under the headline, first report marked, >4 collapse into "+N"), 48 h, 600 max; tags crude = crude-market words, oil = any oil/oil-market headline, india = Indian energy names (ONGC, IOC…) or MCX/India/rupee/NSE beside an energy word, so gold and holiday stories don't match). Includes OpenTerminal's own OIL sources (Google `OIL stock`, Yahoo `OIL`); strict feeds keep only headlines with an energy keyword, keeps them in memory, archives every touched story to Postgres `news` after each poll (`jsonb_to_recordset` upsert; note Bun needs `::text::jsonb` or it double-encodes the JSON string; **`first_seen_at`** (`infra/sql/011_news_first_seen.sql`) is when WE first saw a story, set once on insert and deliberately absent from the `ON CONFLICT` update, guarded by `newsFirstSeen.test.ts`, because `published_at` is the feed's own time and `updated_at` moves on every touch; rows archived before 2026-10-22 13:02 IST stay NULL and are never backfilled, a guessed time would contaminate the sentiment study in `research/sentiment/`), restores the last 48 h from the archive on start (Redis `news:latest` as fallback), and pushes new items on WS topic `news` (`{type:"news", items}`; full list on subscribe).
- `apps/drishti-core-api` — NestJS running under Bun (Bun emits decorator metadata; no nest-cli). Port 3001. `/bars?symbol&tf` = provider history (`history.ts`: Yahoo for NYMEX, Upstox for MCX) cached 30 s and written through to the `candles` hypertable; falls back to `candles` + `bars_1m` rollup when the provider can't answer. `news.controller.ts`: `GET /news?tags&before&limit&q` pages the archive (panel "Load older"; `q` = literal ILIKE on headline/outlet, matching the panel's search box via shared `matchesQuery`; empty list without DB). The stream trims archive rows older than 180 days at start and daily. `history.ts` gets MCX front months from Redis `fronts` or, without Redis, from the stream's `GET /fronts`. `upstox.controller.ts`: OAuth login → token in Redis `upstox:token` (expires 03:30 IST) which the stream polls; otherwise `UPSTOX_ACCESS_TOKEN` from `.env` is used (feed + history; status reports `via: login|env`); secrets only in `.env`, token never returned or logged.
- `apps/drishti-web` — Vite React SPA, port 5173. Vite proxies `/api`→3001, `/ws`→3002; `VITE_API_URL`/`VITE_STREAM_URL` override for packaged Tauri.
  - `src/store.ts` — market data only (WS connection, latest `Quote` per symbol). `Feeds.tsx` = Settings → Data feeds (Upstox connect + provider health via the `/stream` Vite proxy).
  - `src/workspace.ts` — persisted (localStorage) workspace: widgets, react-grid-layout layout, Bloomberg-style link groups (`group: null` = pinned to own symbol; `loadSymbol` on a grouped widget changes the whole group). A new panel joins the focused panel's group **unless that group already holds a panel of the same type** (a group shares one symbol, so a second chart would follow the first): it then starts pinned on the same symbol, so several charts can each show their own; a chart added with a symbol (the palette's `CL GP`) is pinned too. Panel ids carry a counter so two panels added in the same millisecond never share an id.
  - `presets.ts` + workspace store: five built-in workspaces (MCX crude, Natural gas, Options, Research, Live watch) and user-saved ones (`saved`, `saveWorkspace`/`loadWorkspace("preset:…"|"saved:…")`/`deleteWorkspace`, copies via `structuredClone`, max 20). Listed at the top of the sidebar and switched with F1…F9 (presets first, then saved; handled in App.tsx).
  - `HelpDialog.tsx` — shortcuts, panel codes (from `MNEMONICS`) and a glossary (OI, ATP, PCR, STALE…); opens with `?`, the topbar `?` button, and once on first run (`helpSeen` setting).
  - Accessibility (audited with axe-core in both themes: zero violations except the transient flash animation): `--muted`/`--up`/`--down`/`--accent` meet 4.5:1 contrast on their panels in dark and light; panels sit in `<main>`, brand is the page `<h1>`, in-panel section titles are `h2`; scrollable panel bodies are keyboard-focusable regions; one global `:focus-visible` outline. Keep these when adding panels. Watchlist rows draw a sparkline from the store's session `trail` (`spark.ts`).
  - Alerts: shared `alerts.ts` (pure `check`/`crossed`/`describe`: price cross, day move vs previous close, headline keyword, minutes before a release such as EIA) tested; web `alertsStore.ts` (persisted alerts + history, transient toasts), `alertEngine.ts` (subscribes to the market store + 30 s calendar check, fires toast + optional beep + Notification API; last-seen values kept out of the store; only headlines under 15 min old count, since the stream sends the backlog on connect), `AlertsPanel.tsx` (panel `AL` + `Toasts`). Alerts run only while the app is open (no server-side delivery yet).
  - `AdvancedChart.tsx` (panel `AG`, optional): openalgo-charts 2.6.7 (Apache-2.0, pinned) full widget (drawing tools, 100+ indicators, replay, Heikin Ashi/Renko…) lazy-loaded (~0.4 MB gzip in separate chunks) on our data via `advFeed.ts` (`DataFeed`: `getBars` from API `/bars`, `subscribeBars` from the quote store with the same `applyTick` as our Chart; intervals limited to 1m/5m/15m/1h/1D). Created once per panel, symbol/theme changes via its API, drawings/layout persisted by the library under `drishti-adv-<id>`. It is now the default chart: registry key `advchart` titled "Chart" (code `GP`, Alt+1, used by the built-in desks and the default workspace); the former lightweight "Simple Chart" (`GS`) was removed (saved layouts lose only that panel); its indicator maths lives on in shared `indicators.ts` (SMA, EMA, Bollinger, RSI, MACD matching TradingView's Pine definitions, VWAP anchored to the exchange day), used by the briefing and as the reference the library's are checked against. Checked before the switch: its MACD (converges to ours after ~100 bars: it seeds EMAs with an SMA, we seed like Pine), Bollinger and session VWAP (resets at the exchange day) match ours (`advIndicators.test.ts`); Heikin Ashi/Renko etc. need the `openalgo-charts/transform` tier (imported); settings dialog and phone width work; axe finds only redundant `aria-pressed` on its interval radios (upstream). Replay (panel's "⏮ Replay" bar: play/pause, step back/forward, 1–25×, stop): `ReplayController` over the candles stored in Timescale (`GET /bars?…&source=db` = stored only, no provider call), forming each 5m/15m bar from stored 1m bars when available, starting 150 bars before the end; live candles are tracked but not drawn while it runs (`ourFeed(isPaused)`), and Stop restores the full live history. Checked against TradingView's own 5m MCX:CRUDEOILX2026 bars: stored OHLC within 1 tick on 90–95% of highs/lows/closes (opens 73%, ±1–2 ticks either feed), volume median ratio 1.00; replay reproduces every stored bar exactly. Its RSI and EMA were checked equal to ours in `advFeed.test.ts`. Created with `branding: false` (their supported option: no corner mark or toolbar label; their NOTICE ships with the package). Saved widget state lives in IndexedDB `openalgo-charts-widget` under `drishti-adv-<widget id>` (so built-in desk widget ids are prefixed with the desk key); `advStorage.ts` strips the old viewport/pinned ranges from saved states on read (`stripView`) and `healedRange` (checked every 0.7 s for 8 s after creation, a symbol/interval change or replay stop) moves a view that points past the loaded bars back onto the latest ~60 — a stale viewport from a 3,600-bar history applied to the 175 loaded bars used to leave the plot blank. Dev console handle: `window.__adv[widgetId]`.
  - AI briefing (`BriefingPanel.tsx`, panel `BR`; approach borrowed from TradingAgents' analyst → bull/bear → decision → reflection loop, original code): the web app gathers facts (`gatherContext`: live quote, last 200 bars, headlines for the instrument's topic, next-48 h calendar, MCX options PCR/max pain); shared `briefing.ts` `buildContext` computes every number (RSI, EMAs, MACD, Bollinger position, VWAP, change over N bars) plus shared `stats.ts` (annualised realized vol and its percentile in the loaded history, ATR, Hurst exponent by rescaled range with a trending/mean-reverting/random regime flag at 0.58/0.42, max drawdown and distance below the peak; annualisation assumes ~14 trading hours a day, exact only on 1D) so the model never does arithmetic, and defines the system prompt (facts only, cite evidence, headlines are untrusted data, no trade advice). API `POST /briefing` (`briefing.controller.ts`) calls Claude (`@anthropic-ai/sdk`, `messages.parse` + zod schema, `BRIEFING_MODEL` default `claude-opus-5-5`, effort medium) — key only server-side (`ANTHROPIC_API_KEY` or `ant auth login`), 503 hint without it; cached 5 min per symbol, 20 calls/hour cap, context ≤ 40 KB. Each briefing is journaled in localStorage (`useJournal`, last 30) and graded after 30 min against price (`scoreBriefing`: direction, ±0.3% band for neutral). Position-aware (opt-in checkbox "Include my position", setting `briefingPositions`, MCX only since Upstox doesn't carry NYMEX): API `GET /positions` reads Upstox `/v2/portfolio/short-term-positions` (5 s cache, 403 hint when the token can't see the portfolio), shared `positions.ts` `parseUpstoxPositions` keeps open positions in our four MCX underlyings and `positionContext` separates open / flat / unavailable (a failed read is never treated as flat); nothing is sent to the AI service unless ticked. Response shape taken from Upstox's docs, not yet seen live (the current token gets 403). **Grounding** (shared `grounding.ts`, tested incl. mutation checks: weakening the tolerance or the unknown-field rule fails tests): the prompt ends with a "Citable fields" map (`citableFields(ctx)`: every number, provenance quality and source, headline as `news.N`, event as `events.N`, by path), the model must give each bull and bear point `cites: [{field, value}]` copied from it and may not write numbers that are not in it, and **code** (not a second model call) then checks the answer: each cite is resolved and compared (numbers within 0.5% or a hundredth, headlines may be quoted in part), prose figures that are not in the data are flagged (whole numbers under 100 and years ignored), and a summary that calls delayed, stale or closed data live is flagged. Each point is `verified`, `wrong` (a cite contradicts the data or names no field) or `unverified` (no cite, or a loose figure). `writeGrounded` asks again once when something is wrong, sending the earlier answer plus exactly which cite was false and what the data holds, and keeps the better answer (a failing or worse retry keeps the first; never more than two calls; the second call also takes from the 20-per-hour limiter). The API returns `grounding` (report) and `attempts`; the panel shows a check, cross or question mark per point with the data's true value under a wrong one, a one-line "N of M points checked against the data" and any odd summary figure; wrong points are kept and marked, never hidden. Briefings saved before this say "not checked". The controller's model call is replaceable (`controller.complete`), which is how the retry, refusal and cache paths are tested with no key (`briefing.controller.test.ts`); **not yet run against the real model: set `ANTHROPIC_API_KEY` and press the button to see how often it cites wrongly.** A refusal is a 502 that points to the Recap panel (no automatic fallback yet).
  - Instruments you add (Settings → Instruments, `InstrumentsSettings.tsx`): the six futures stay in code; MCX and NYMEX energy futures can be added in the UI. Shared `parseCustomInstrument` (`customInstruments.ts`, tested) validates the form (exchange decides time zone, currency, delay and feeds, so those cannot be mistyped; lot must be "units unit" because costs and paper trading parse it; at most 20) and `setCustomInstruments` changes `INSTRUMENTS`/`SYMBOLS`/`instrument()` **in place**, so every module that imported them sees the change (never copy `SYMBOLS` into a constant at load). The stream owns the table (`custom_instruments`, `infra/sql/008_instruments.sql`, stored as the form fields and re-validated at every load) and the routes `GET/POST /instruments`, `DELETE /instruments/:symbol` (`instrumentRoutes.ts`: Origin allow-list, rate limit; MCX underlyings are checked against Upstox's instrument master; built-ins and instruments with an open paper position cannot be removed). It reloads every 60 s and after each change, drops the removed symbol's prices, refreshes front months so the new future gets Upstox and TradingView codes at once, and the Yahoo provider reads its instrument list on every poll; the API syncs the list from the stream every 30 s (`instruments.sync.ts`), the browser at start-up and every 60 s (`instrumentsClient.ts`, then `instrumentsRev` remounts the app so pickers re-read `SYMBOLS`). Verified live: MCX ZINC and NYMEX RB got prices from two feeds, history from `/bars` and a paper quote within seconds. Not covered: the options chain (`/options` still accepts only the four MCX underlyings), the COT mapping, the built-in desks and the MCP server (its tools take a fixed enum of the six, so an agent cannot trade an instrument you add). In the test runner (`bun test`) happy-dom's `Request` drops the Origin header, so route tests set it after construction.
  - **USD/INR** (`FX:USDINR`) is a seventh built-in instrument with exchange `FX`: live from TradingView's scanner (`FX_IDC:USDINR`, polled with the others, a few seconds behind a true tick) and Yahoo (`INR=X`, also gives the 1m to 1D history through `/bars`), so it gets the quote badge, drift check between the two feeds, watchlist row, the advanced chart and stored candles like any symbol. Four decimals, no volume, candles bucketed in IST. Session rule `fxSession` (Sunday 17:00 to Friday 17:00 New York, no daily break) drives LIVE/STALE/CLOSED and the status bar. Deliberately not for: paper trading and costs (MCX only), the futures curve (`curveInstruments()` and the Curve panel skip `FX`), the energy recap, options, COT, the MCP server (fixed enum of the six futures), news (the linked filter shows all headlines for a topic with no tags). TradingView's other USD/INR listing (`FX:USDINR`) read about 0.9% higher than `FX_IDC` when checked; IDC agrees with Yahoo, which is why it was chosen. Compare with your broker before using it for anything but context. `Instrument.exchange` is `"MCX" | "NYMEX" | "FX"`; the add-instrument form still offers only MCX and NYMEX.
  - `src/Sidebar.tsx` — left rail listing every `WIDGETS` type (code from `MNEMONICS`, Alt+1…9 in registry order via `PANEL_TYPES`, handled in App.tsx with `e.code`), Reset layout, collapse (`sidebarCollapsed` setting); phone width = overlay from the ☰ button.
  - `src/Grid.tsx` — panel grid (react-grid-layout v2, `Responsive` + `useContainerWidth`). Named Grid, not Workspace, because `Workspace.tsx` and `workspace.ts` collide on case-insensitive filesystems.
  - `src/widgets.tsx` — widget registry `WIDGETS` (chart, quote, watchlist, tv; `linked`/`showSymbol` flags drive panel chrome). New widget = component + registry entry + `SIZE` and `WidgetType` in workspace.ts (+ optional mnemonic in command.ts).
  - `src/TvWidget.tsx` — live HLS TV; lazy-loads `hls.js/light` (hls.js first, native HLS only as fallback: Chrome reports native support but fails many streams). `BUILTIN_CHANNELS` (Bloomberg US/EU/Asia/TV+/Originals via bloomberg.com manifests, CNBC-TV18 via Network18's CDN, NDTV Profit) + user channels from settings (`tvChannels`), deduped by URL; selected channel persisted per widget (`Widget.channel`); first built-in (Bloomberg TV+) is the default. Pause/resume is DVR-style; "GO LIVE" lag = `hls.latency - hls.targetLatency` while playing, wall clock while paused (latency only refreshes per playlist reload when paused). Only official broadcaster streams, never third-party restreams.
  - `NewsWidget.tsx` — energy headlines from the store (`news`), filters Linked (instrument `topic` → `TOPIC_TAGS`: crude instruments show crude + oil) / All / Crude / Oil / Nat Gas / India; links opened only if `isSafeUrl`.
  - `ChokepointsPanel.tsx` — tankers per day through Hormuz, Bab el-Mandeb, Suez, Malacca, Cape of Good Hope and Bosporus (API `GET /chokepoints?id&days`: IMF PortWatch ArcGIS, free and keyless, a few days behind, cached 1 h with a stale fallback; shared `chokepoints.ts` does the parsing, 30-day average vs the same days a year ago and the normal/reduced/disrupted flag at -30%/-70%). Command `CHK`.
  - `CurvePanel.tsx` (panel `CRV`) — futures curve for any of our six instruments: API `GET /curve?symbol` asks TradingView's public scanner for the next 12 dated contracts (`curveCodes`: root + month letter + year, so one request serves MCX and NYMEX; expired contracts that TradingView still returns are dropped by `parseCurve`), 10 s cache with a stale fallback; shared `curve.ts` adds calendar spreads, the shape (front-to-last change over 0.5% of the front price = contango/backwardation, else flat) and the nearest roll as an annualised rate. MCX natural gas lists only a few months and is seasonal, so first-to-last can disagree with M1–M2; read both. `curveInstruments()` is a function because `index.ts` re-exports `curve.ts` (a top-level `INSTRUMENTS` read hits a circular import).
  - **JODI was removed on 2026-10-22** (owner decision, see `docs/redesign/ASSESSMENT.md`): monthly, about six months late, nothing a futures trader acts on. Panel, route, MCP tool `get_jodi`, parser, fetcher, source check and fixture are gone; layouts saved with a JODI panel lose only that panel (`migrateWorkspace` in `workspace.ts`, persist version 3, instead of resetting the whole layout).
  - `EiaPanel.tsx` (panel `EIA`) — EIA Open Data v2: API `GET /eia` reads ten series through `api.eia.gov/v2/seriesid/…` (weekly US crude ex SPR, Cushing, gasoline, distillate and SPR stocks, refinery utilisation, product supplied; daily WTI, Brent and Henry Hub spot; list in shared `eia.ts` `EIA_SERIES`), hourly cache with a stale fallback, and shared `summarizeEia` compares each with the previous reading, the same week last year and the average of the same week over the previous five years. Needs a free `EIA_API_KEY` (`.env`): without it the API answers 503 with that hint, and the shared `DEMO_KEY` is never used (about 10 calls an hour). Stock builds are coloured with the down colour. Checked live with a real key (crude −8,557 kb on the week of 2026-10-09, matching the calendar's EIA actual). EIA's routes take 1–45 s for the same call (natural gas worst), so each series loads on its own in the background (`refresh`, 90 s timeout, 5-minute retry pause), one request waits at most 8 s, and the panel re-asks every 5 s while any series is still missing. After editing `.env`, restart the API: `--watch` does not reload env files. Separate from the calendar's keyless EIA CSV actuals.
  - `RecapPanel.tsx` (panel `RCP`) — a plain-language recap of the linked instrument with no AI and no key: shared `recap.ts` `buildRecap(ctx, extras)` turns the briefing facts (`gatherContext`: price, day range, EMA/RSI trend, volatility percentile and regime, options PCR/max pain, next release, headlines under 3 h old) plus the futures-curve summary, managed-money COT positioning and EIA crude-stock change into fixed-template sentences, each from one rule with one threshold (day range ≥80%/≤20% = near high/low, RSI ≥70/≤30, vol percentile ≥80/≤20); anything missing is left out. The reply lists the points that did not check out with the true value, so the agent can correct and submit again (the first stays on record). 12 submissions an hour; it stores a research note and places no order. This is how the AI is used without paying for API calls: the writing runs in Claude Desktop or Claude Code on the user's subscription, and the app does the checking. The MCP `call` helper now prefers the HTTP error's `message` (Nest puts the reason there and a class name in `error`; the stream puts it in `error`). Tested in `briefing-facts.test.ts`, `briefingSubmit.test.ts`, `server.test.ts` and end to end (`bun run e2e`: a stdio client reads the context, submits a wrong figure, is told which point and the true value, resubmits, and the panel shows ✗ then ✓); `db:clean` removes the e2e briefings (summary starting `[e2e]`). Tested in `apps/drishti-mcp/src/server.test.ts` (real MCP client over an in-memory transport, fake network) and end to end in `bun run e2e` (a stdio client spawns the real server).

Provider contract (R13, shape borrowed from OpenBB's Fetcher, original code): shared `fetcher.ts` defines `Fetcher<Q, Raw, R>` (`key`, `extract` = the only step that touches the network or a key, `transform` to our standard model, `isUsable`, `ttlMs`, optional `credentials` env names + `instructions`) and `createRunner(io)`, which gives every source the same behaviour: a capped `LruCache`, one in-flight request per key (two panels asking at once share one fetch), the last good copy served as `stale` when the source fails (with a 5-minute pause before the next attempt and the real fetch time kept), an empty or implausible result treated as a failure so it never replaces a good copy, and a `SourceError` carrying a "Set X in .env (how to get a key)" hint when a credential is missing, with no request made. `fetch`, `env` and the clock are injected (`FetchIO`), so tests run fetchers against fake responses (`fetcher.test.ts`, `fetchers.test.ts`). `fetchers.ts` holds `cotFetcher`, `chokepointFetcher`, `curveFetcher` (their controllers shrank to validation + `serve(fetcher, query)` from API `source.ts`, which maps `SourceError` to 503) and `SOURCES`, a registry of every external source with its credentials and whether a fetcher serves it (the base for canaries R14 and the data-quality console R25). **A new source is a Fetcher, not a hand-written controller cache.** Not converted yet (different shapes): EIA open data (ten series loaded in the background behind a limiter), the calendar (several sources merged), news RSS, Upstox/Yahoo/TradingView live feeds, options chains. The standard models are the existing types (`Quote`, `Bar`, `NewsItem`, `CalEvent`, `CotRow`, `CurvePoint`, `TransitDay`, `EiaSummary`).

Recorded fixtures (R36): `bun run fixtures:refresh [id ...]` (`scripts/fixtures.ts`) runs eight sources through their real code paths against the live providers and saves the real responses, trimmed, to `packages/shared/fixtures/<id>.json` (CFTC COT, IMF PortWatch, TradingView curve, EIA WPSR and gas-storage CSVs, FRED CPI, Yahoo chart, EIA v2 stocks (needs `EIA_API_KEY`; the key is scrubbed from the recorded URL, `scrubUrl`). A sample's own `check` must pass on the live data before anything is written. `fixtures.contract.test.ts` replays them (`replayIO`: answers only from recordings, an unrecorded request is an error, the clock stands at the recording time so dated codes and year files match) and asserts each parser still yields usable data, plus that no fixture holds a credential. Proven to bite: renaming a CFTC field or the gas-storage header in a fixture fails the test. **A parser failure after a refresh means the provider changed its format; without a refresh it means our parser regressed.** Samples live in `fixtureSamples.ts` (add one per new source, next to its Fetcher). Refresh when a parser misbehaves in production or every few months; the fixtures are committed (~360 KB).

Source canaries (R14): the fixture samples double as live checks. Shared `canary.ts` `runCanary(sample, io)` runs a source's real code path against the live provider and returns `ok`, `unreachable` (a request failed or threw: no connectivity is never a pass), `format` (it answered but the result fails the source's own check: the provider changed what it sends or our parser broke, which an uptime ping misses) or `skipped` (a needed key is not set, with the reason); `formatCanaryTable` makes the start-up table. API `canary.controller.ts` (`CanaryService`, started with the API): 4 s after boot it runs every light sample (12: CFTC, PortWatch, TradingView curve, four RSS feeds, EIA CSVs and v2, FRED, Yahoo) three at a time and prints the table to the console, then re-runs each hourly (`everyMs`); a sample with a longer `everyMs` (a daily-sized download) runs 10 minutes after boot and then at its own pace so dev restarts do not repeat it (none at the moment). Results are kept in memory (24 per source); `GET /canaries` returns the latest per source with recent statuses plus the `SOURCES` registry; failures also log a warning; `CANARIES=off` disables it. A canary that depends on the time of day is a bug in the canary: the Yahoo sample asked for `range=1d` of 5m bars, and Yahoo's "1d" is the exchange's calendar day, so for the first ~100 minutes after New York midnight it holds under 20 bars and the check cried "format" (failed three smoke runs in a row); it now asks for `range=5d`. Not covered: Upstox (needs a token and a market), live feeds and the Forex Factory JSON; cross-source price agreement belongs to R2. The data-quality console (R25) will draw these results. Samples are shared with the recorded fixtures (`fixtureSamples.ts`), so a new source gets both by adding one sample.

Source risk and explicit-only fallbacks (R15): the `SOURCES` registry (shared `fetchers.ts`) now gives every external source a `risk` (low = official or authenticated, medium = unofficial public endpoints, high = already throttles us: Forex Factory), a `fallback` (`auto`, or `explicit` = only when the user turns it on because it would mislead or cost money) and a one-line reason. Explicit-only: **TradingView MCX continuous (`1!`)**, which rolls late and shows the wrong contract in the last days before expiry (shared `tvTickerFor`: an MCX instrument with no known front month now gets NO TradingView ticker, in the price feed, unless `TV_MCX_CONTINUOUS=1`; NYMEX keeps its own correct `1!`), and the **Anthropic API** (costs money: only on the button). Canaries probe riskier sources less often (`canaryInterval`: low 1×, medium 2×, high 6× the base). **User-agent pool** (shared `userAgents.ts`): the eight hardcoded Chrome strings are gone; `userAgentFor(host)` picks one of five browser strings per host, stable for the life of the process (a restart may change it), used for the unofficial sources (TradingView, Yahoo, news feeds, Forex Factory). **Official data hosts get no browser string** (`OFFICIAL_HOSTS`: FRED, EIA, CFTC, PortWatch, Upstox, Anthropic): the live check found FRED stalls for 20 s on a browser User-Agent but answers in 0.1 s to the runtime default, which would have silently broken the calendar's US macro actuals; Dev gotcha: `bun --watch` does NOT watch `packages/shared` ("not in the project directory"), so after editing shared code restart the API and stream (they also die if reloaded halfway through a multi-file edit).

Caches and fan-out (R27): every cache in the API keyed by anything a caller can influence is an `LruCache` (shared `lru.ts`; briefing, bars, options, COT, curve, chokepoints...), enforced by `apps/drishti-core-api/src/caches.test.ts`, which fails if a module-level `*cache* = new Map` appears: use `LruCache` for the next one. `RateLimiter` has a hard `maxKeys` (10,000; past it the oldest key is dropped) on top of its sweep, so a flood of distinct client keys inside one window cannot grow memory. Third-party fan-out goes through shared `concurrency.ts`: `limiter(n)` (a gate shared by callers, used by EIA: at most 4 of ten series in flight) and `mapLimit(items, n, fn)` (order kept; catch per item for best-effort).

Security defaults (keep them): API and stream bind `HOST` (default 127.0.0.1); browser access limited to `WEB_ORIGINS` (default Vite + Tauri origins, shared `allowedOrigins`/`isAllowedOrigin`), enforced by Nest CORS, the stream's `/health` CORS header and a WS `beforeHandle` origin check; `RateLimiter` (shared) on API requests and WS messages; WS subscriptions validated against `SYMBOLS` + "news"; API responses gzip-compressed; Docker ports bound to 127.0.0.1.

Market status: shared `sessions.ts` (`mcxSession` Mon–Fri 09:00 IST to 23:30/23:55 by US DST, overridden by Upstox's day timings from API `GET /market/sessions`; `nymexSession` CME Globex Sun 18:00–Fri 17:00 ET with the 17:00–18:00 break; `freshness` live/stale/closed). Heartbeats carry `seen` (when each symbol's active source was last heard from, incl. unchanged polls), which `useFreshness` (web `market.ts`) combines with the session: STALE/CLOSED badges + dimmed prices; `StatusBar.tsx` (bottom) shows sessions, IST/NY/London clocks and feed ages. **The exchange's own status** (Upstox `GET /v2/market/status/MCX`, API `GET /market/status`, cached 30 s, logging every distinct value once) corrects the MCX rules in both directions through shared `withStatus` (a fresh `NORMAL_OPEN` or `NORMAL_CLOSE` wins; a status older than 2 minutes, missing, or any value we do not know is ignored and never read as closed): the stream polls it every 30 s, uses it in `symbolLive` (paper orders), puts it in every heartbeat (`mcxStatus`) and `/health`, and the web store hands it to `useSessions`/`symbolFreshness` and the status bar tooltip. The briefing's server-side facts still use the day override only.

Live option quotes (Upstox feed, spec 2 in `docs/redesign/UPSTOX_PLAN.md`): the stream's one Upstox connection (mode `full`) also carries option contracts that clients ask for. A client sends `{watch:[instrument keys]}`; `optionWatch.ts` `OptionWatch` accepts only keys that match `MCX_FO|digits` and appear in the public master (`loadOptionKeys`, refreshed hourly; any well-formed key until it first loads), at most 24 per request and 40 in all, each kept for 60 s unless asked again, and adds or drops them on the open socket with `sub`/`unsub` (`subscriptionDiff`) without reconnecting. Shared `optionQuote.ts` `parseOptionFeed` turns a decoded entry into an `OptionQuote` (price, exchange trade time and our receipt time, five depth levels with empty ones left out, OI, volume, ATP, IV in percent (the feed sends a fraction), delta/theta/gamma/vega/rho); `optionQuoteProblem` refuses impossible values. Every tick is published on WS topic `options` as `{type:"opt",q}` (about one a second per contract, tested live: bid/ask, 5 levels, OI, IV and greeks arrive for MCX options) and the web store keeps the newest per key. `/health.options` reports watched and known contracts, message count and **lag** (exchange trade time to our receipt, measured only on a NEW trade, because a quiet strike repeats its old trade time; MCX trade times have one-second resolution). `bun run smoke` checks a watched pair streams and malformed or unknown keys do not. Not built yet: showing the traded strike's premium in a trade block (there is none in the app yet), and acceptance of 'within 1 s at the 95th percentile over 15 minutes' needs a busy evening to measure (read `lagP95Ms`).

Option candle recorder (spec 3 in `docs/redesign/UPSTOX_PLAN.md`): Upstox serves one-minute option candles (with open interest, a candle for every minute from the first trade, forward-filled) for LIVE contracts only, and its expired-contract API does not cover MCX, so the API copies them while the contract lives. `optionCandles.controller.ts` (`OPTION_CANDLES=off` disables it) checks every 5 minutes and, once after each MCX session has closed and settled (`shouldRecord`: 10 minutes after `lastMcxClose`, never twice for one close, at once if never recorded), runs `recordOptionCandles` (`optionCandles.run.ts`): the first two expiries of CRUDEOIL and NATGASMINI, 11 strikes around the money of each expiry's own future (`selectRecordingContracts`, 88 contracts), earlier days from the dated candle endpoint and **today from the intraday endpoint (the dated one never has the current day)**, three requests at a time, `validateBars` before storing, a contract failing does not stop the rest, and the run counts (sets `kv option_candles_last_run`) only if at least 80% of the contracts were fetched, else it waits 30 minutes. Storage: Postgres `option_contracts` and `option_candles` (hypertable, primary key `(key, time)`, `INSERT … ON CONFLICT DO NOTHING`: append-only and idempotent; migration 013); `db:clean` never touches them. Routes: `GET /option-candles/status` (rows, contracts, first and last candle, last run) and `GET /option-candles?key=MCX_FO|…&from=&to=` (IST dates, at most 40 days, 25,000 rows). Checked live on 2026-10-22: 119,937 candles for 64 contracts (the other 24 had no trades yet), 0 differences from a fresh Upstox fetch for the at-the-money call on 21 Oct (870 of 870 candles, open interest included). A tick guard once let two recordings start together (found by its own test; the guard is now taken before the first await). The first intraday-aware run happens after tonight's close.

Upstox account access (spec 5 in `docs/redesign/UPSTOX_PLAN.md`, partly): Upstox answers its account endpoints (funds, orders, trades, positions, profile, P&L and historical trades) **only from the static IP registered in the Upstox app** (a 401 `UDAPI1221`; tested 2026-10-22 from this machine), while market data works with any valid token. API `GET /auth/upstox/account` (cached 60 s) asks for the profile and returns only `{access, hint}` with `access` one of `ok`, `static_ip`, `token`, `no_token`, `unavailable` (shared `upstoxAccount.ts` `classifyAccountAccess`; nothing from the profile is returned or stored); Settings → Data feeds shows it under the Upstox line; the positions route now says the static IP instead of blaming a read-only token. **Not built, waiting for a registered static IP:** funds for the capital rule, the real-trade journal from trades and order history, Upstox's own P&L and charge reports, and the Portfolio Stream that would detect the owner's entry and exit.

Bar and quote rules (shared `bars.ts`, tested): **`Bar.time` is the bar's OPEN in epoch seconds**; **`Bar.oi` (optional) is the open interest at the bar's close** (a level, never summed): Upstox sends it as the seventh field of every futures and options candle, so MCX bars carry it from `parseUpstoxCandles` through `normalizeBars`, `candles.oi` (migration 012, NULL for Yahoo bars and for candles stored before it; a COALESCE keeps an old reading when a refetch has none), `/bars` (a missing OI is an absent field, never null) and the advanced chart, whose bar contract has an `oi` field for its open-interest studies; `validateBars` drops an impossible OI (negative, not a number) from the bar and keeps the prices. a bar closes at `time + timeframe` and is only available then, so anything reasoning "as of now" (briefing facts, any replay or backtest) uses `completedBars`, never the still-forming bar (the backtester already fills at the next bar's open). `validateBars` drops impossible bars (high under open/close/low, low above them, non-positive or non-numeric prices, negative volume, non-integer time) on every provider ingest in the API's `history.ts` (Yahoo and Upstox) before they are cached, stored in `candles` or drawn, and logs the count; `quoteProblem` makes the stream's `accept()` reject impossible quotes (non-positive price, negative volume, high under low) before they are published, stored or counted as "heard from", with a `rejected` counter and last reason in `/health` (a momentarily crossed bid/ask is allowed). Reliability: the stream publishes `{type:"hb"}` every 15 s; the web store reconnects after 45 s of silence and bumps `epoch`, which makes every `Chart` re-fetch history (fills gaps from the outage). Each panel body is wrapped in `PanelBoundary` (PanelBoundary.tsx), so one crashing panel shows a retry instead of blanking the app. MCX front month rolls by volume (`rollByVolume`: next contract once it out-trades the nearest; checked hourly via TradingView dated-contract volumes).
